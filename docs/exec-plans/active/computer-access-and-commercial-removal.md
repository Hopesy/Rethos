## 目标与产品决定

完成三件相关工作：移除原产品的商业托管与订阅实现；让用户管理自己的电脑接入服务；让 Bot 和会话选择具体执行电脑，并让界面、工具路由和权限执行保持一致。

| 概念 | 职责 | 建议界面 |
| --- | --- | --- |
| 电脑接入 | 电脑向哪个服务器开放、允许哪些能力、暂停与撤销 | 全局设置 → 电脑接入；本机连接器入口 |
| 工作位置 | Bot 默认目标、当前会话固定目标、实际执行目标 | Bot 设置、会话选择器、电脑面板 |
| 已连接电脑 | 用户实际使用的物理机或既有操作系统桌面 | `zhouh · Windows · 在线` |
| 私有桌面 | Rethos 管理的隔离虚拟机或容器 | `项目开发桌面 · 自有 VPS` / `本地测试桌面` |
| 连接方式 | 同机调用、SSH、原生连接器出站通道 | 电脑详情中的技术信息 |

本机桌面独立展示为“已连接电脑”，与私有桌面共用电脑身份、能力、状态和权限契约。公网地址、内网位置和连接方向作为设备属性。已有 VPS 实现通过 SSH 管理远端 Docker；已发布的原生连接器通过出站 HTTP(S) 注册、长轮询、租约与结果回传工作。其他受配置控制的网络桥接能力继续按实际用途审查。

商业移除范围包括原产品的托管账号、套餐、购买、试用、充值、赠送额度与 Boat 付费桌面。用户自配模型/API、MCP、SSH、自有 VPS、原生电脑接入和通用权限能力继续保留。对包含通用能力的混合模块，先抽取依赖再删除商业部分。

## 已确认的问题与代码依据

| 编号 | 发现 | 影响与依据 |
| --- | --- | --- |
| F01 | 商业页面主要在导航层隐藏 | `src/components/SettingsModal.tsx` 将 `cloudAccount` 等入口重定向；对应页面和调用链仍在仓库。 |
| F02 | 桌面主进程仍引用商业账号、购买与套餐模块 | `electron/main.mjs` 导入 `cloud-account.mjs`、`cloud-plan-ipc.mjs`、`cloud-buy.mjs`；`ensureCloudAccount()` 仍串联同步、共享与窗口状态。需要逐项判定注册和运行条件。 |
| F03 | 服务端仍有 Boat 和商业运行分支 | `server/index.ts`、`server/host/cloud-computer-power.ts`、`server/cloud-computer-tools.ts` 引用 Boat；`server/new-bot-defaults.ts` 仍接受 `box` 后端。 |
| F04 | 现有开源检查覆盖范围较窄 | `scripts/check-oss.mjs` 检查 enterprise 目录、产品身份和许可证；商业模块依赖与外联行为还需专门验收。 |
| F05 | 工作位置只存储类型 | `shared/wire.ts` 的 `Surface` 为 `cloud/vm/local/browser`，会话 `surface` 和 Bot `computer` 缺少具体已连接电脑 ID。 |
| F06 | 两套选电脑入口并行存在 | `select_computer` 选择 surface；`shared_computer` 每次接受 `computer_id`。`server/host/shared-computer-turn.ts` 核验所有者和任务代次，尚未读取统一的会话电脑绑定。 |
| F07 | 保存授权可能改变电脑身份 | `electron/computer-sharing.mjs` 的 `save()`、`lendOwn()` 生成新的 `id` 和 secret；普通重启复用已存记录。固定目标之前需区分稳定设备身份与可轮换授权。 |
| F08 | 接入管理依赖本机桌面桥接 | `ComputerSharingSettings` 通过 `window.ogb.computerSharing` 读写；VPS 网页缺少对应的完整管理路径。现有公开接口提供状态和连接器协议操作，disconnect 要求连接会话与 secret。 |
| F09 | 暂停与撤销的作用域不同 | `pause()` 遍历多个 own/cloud 环境；`revoke(env)` 面向一个服务器。单个服务器设置页需要准确表达并执行自己的作用域。 |
| F10 | Bot“关闭电脑”的语义需要收拢 | `shared-computer-turn.ts` 仅对 `computer_tools/computer_call` 检查 `computer === off`；文件和终端继续经过各自权限规则。界面需与最终执行规则一致。 |
| F11 | 工作目录和桌面预览沿用 surface 路由 | Bot `cwd`、会话固定目录、ComputerPanel 的预览/接管入口还需携带目标电脑。Windows 本机与 Linux VPS 的路径需要按目标解析。 |
| F12 | 当前界面补丁尚有显示与配置分离 | 旧 `cloud + box` 在部分选择器中显示为 Auto，存储仍保留旧值；新增连接卡片只展示状态。迁移和目标绑定完成后应以真实配置驱动显示。 |

可复用的基础已经存在：所有者校验、每轮权限检查、目录授权卡片、Bot/会话/任务代次隔离、连接 secret、任务租约、取消和断线重连。主要入口为 `server/shared-computers.ts`、`server/computer-permissions.ts`、`electron/computer-sharing.mjs`、`electron/shared-computer-access.mjs`。

## 进一步验证的风险

- 多 Bot 共用真实桌面：当前请求队列和本机控制锁需要明确连续交互的占用粒度，验证多步点击/输入期间的竞争与取消交接。
- 商业账号逻辑和自有服务器共享的依赖：移除账号恢复、套餐检查和原托管模式后，验证自己的服务器仍能配对、重连、撤销和升级。
- 旧配置、离线电脑、会话固定目标、例行任务和团队委派的迁移：覆盖有真实资源和缺少资源两种情况。
- 电脑离线时的路径使用：实际结果标记来源电脑；跨电脑执行需要显式目标变更。
